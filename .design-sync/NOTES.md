# /design-sync notes — Bear Cub

- **This is a tokens-only sync, on purpose.** Bear Cub is Phoenix LiveView; the skill's component path is React-only and says "never a reimplementation", so there are no components, no previews and nothing to grade. Do not port `BearCubWeb.KioskComponents` to React to feed it. `[ZERO_MATCH] … treating as tokens-only DS` on every build is the expected line, not an error.
- **`.design-sync/pkg/` is a stub package** (the converter needs a named `package.json` and an entry). Only `package.json` and `index.js` are committed; `styles.css`, `fonts.css` and `guides/` are generated by `.design-sync/build.mjs` and gitignored. Always run `cfg.buildCmd` before the converter — a fresh clone has no `styles.css`, and `cssEntry` will be missing.
- **Converter invocation:** `--node-modules .ds-sync/node_modules --entry .design-sync/pkg/index.js`. React is vendored even with zero components, so `.ds-sync` needs `react react-dom` beside `esbuild ts-morph @types/react`.
- **Fonts:** the compiled CSS references Nunito at root-absolute `/fonts/…`. Font `url()`s reached from `cssEntry` are bounded to the package dir, so `build.mjs` splits the `@font-face` blocks into `pkg/fonts.css` (an `extraFonts` CSS, bounded to the repo) pointing at `priv/static/fonts/`. Success looks like `fonts: 2 @font-face rule(s)` and two `.woff2` in `ds-bundle/fonts/`.
- **Re-staging the converter:** the skill's bundled directory lives under a per-Claude-Code-version temp path (`/private/tmp/claude-501/bundled-skills/<version>/…/design-sync`) that does not survive across sessions. `.ds-sync/` is gitignored, so on a fresh clone or after a Claude Code upgrade, type `/design-sync` — the loaded skill names its current base dir — and re-copy from there. A stale `.ds-sync/` still runs; it just runs the old converter.
- **Playwright:** chromium builds 1200 and 1223 were cached on this machine (`~/Library/Caches/ms-playwright`); `playwright@1.57.0` pins 1200. Newer releases want a download.
- **Guidelines** land at `guidelines/guides/design-language.md` (the glob keeps the `guides/` segment). `conventions.md` names that path.

## Known render warns

- `[RENDER_SKIPPED]` on a no-change re-sync — the driver skips the render check when nothing to upload; expected, not new.

- `[TOKENS_MISSING] --tab-height, --page-overflow, --page-scroll-transition, --items` — daisyUI internals set at runtime by its own components; the kiosk uses none of them.

## Re-sync risks

- `conventions.md` is hand-written and enumerates classes, tokens and the icon list. The compiled stylesheet only contains utilities the app uses, so **removing the last use of a class in the app silently invalidates the header**. Re-run the header validation (every named class/token grepped against `ds-bundle/_ds_bundle.css`) on every sync.
- The example JSX in `conventions.md` mirrors `chore_row/1` in `lib/bear_cub_web/components/kiosk_components.ex`; a ruling that restyles the slot or done row should update it.
- `guides/design-language.md` is a lossy regex rendering of `docs/design-language.org` (headings, inline code, bold, link labels). New org constructs there — tables, source blocks, drawers — will come through raw.
- The `.md` rendering flattens `[[file:decisions.org::#dNN][DNN]]` links to bare `DNN`; `docs/decisions.org` itself is not synced, so the design agent sees decision numbers without their text.
- Light theme only: the dark daisyUI theme ships in the CSS but the header tells the agent not to use it.
