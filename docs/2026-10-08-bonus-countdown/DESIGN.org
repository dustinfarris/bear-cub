# Mutability: adaptive. PRD (invariant contract): [[file:PRD.org]]

* Overview

The Early Bird and the evening bonus each pay only before a cutoff, and a cutoff on a clock does not feel urgent to the kids; a parent ends up calling out the time. This design puts the urgency on the kiosk, per kid: while a kid can still earn their bonus and the cutoff is within a set lead time, the left slot of that kid's banner shows a dial and the time left. Whole minutes first, then live ticking seconds for the final stretch. Finishing swaps the countdown for the reward in the same slot; reaching the cutoff unfinished fades it away with nothing in its place.

The whole feature is *one pure module, one more edge on the existing timer, and one banner slot*. No schema change and no new table: the cutoffs and amounts are already data in ~schedule_versions~. Four properties organise the design, one per PRD Success Criterion:

1. *Per kid, to the cutoff that applies to them* (SC-1). The morning uses the one shared Early Bird cutoff, the evening each kid's own cutoff; each column computes its own countdown ([[file:../decisions.org::#d146][D146]], [[file:../decisions.org::#d148][D148]]).
2. *Minutes, then seconds* (SC-2). ~:minutes~ mode above a configured switch point, ~:seconds~ mode at or below it, ticked by the server on the one boundary timer ([[file:../decisions.org::#d145][D145]], [[file:../decisions.org::#d147][D147]]).
3. *Only while the bonus can still be earned* (SC-3). Not finished, not failed, amount above 0, a cutoff present; finishing removes the countdown and the existing badge is the reward ([[file:../decisions.org::#d146][D146]], [[file:../decisions.org::#d149][D149]]).
4. *A quiet end* (SC-4). At the cutoff the state is ~nil~ and the pill fades out; no message, no colour change, no "missed it" ([[file:../decisions.org::#d152][D152]]).

Two changes ride along, settled with the human during design: the evening bonus is *displayed* as *Sleepy Bear* instead of Night Owl, while code and schema keep ~night_owl_*~ ([[file:../decisions.org::#d150][D150]]); and the reward pill is rebuilt to read =EARLY BIRD= / =SLEEPY BEAR= with the bird or bear peeking out of it, so the glyph on the countdown dial is the glyph on the reward ([[file:../decisions.org::#d149][D149]], [[file:../decisions.org::#d151][D151]]). Throughout this document "Sleepy Bear" is the evening bonus the PRD calls the Night Owl.

Canon this builds on, restated so the design reads cold:

- *D8 / [[file:../decisions.org::#d120][D120]] — routines are app constants.* ~:morning~ / ~:evening~; windows, cutoffs and bonuses are append-only data in ~schedule_versions~ (~BearCub.Schedules~). ~Routines.current/2~ returns ~{:active, slug}~ inside a window and ~{:upcoming, slug}~ in a gap, where the kiosk shows the night screen.
- *[[file:../decisions.org::#d121][D121]] — each points term is priced by the version in force at its instant* (for a routine bonus, the last live tap). The countdown is not a price: it looks forward, so it reads the version in force *now*, the same one the live stake chip shows.
- *[[file:../decisions.org::#d124][D124]] — one boundary timer.* ~KioskLive.schedule_boundary/2~ cancels the stored timer before arming the next; boundaries today are window edges and midnight only.
- *[[file:../decisions.org::#d133][D133]] — the verdict's cutoff test is strict.* ~before_cutoff?/2~ in ~BearCub.Chores~ is ~last_completed_at < cutoff~ in local time; a tap one instant before the cutoff earns.
- *[[file:../decisions.org::#d134][D134]] / [[file:../decisions.org::#d135][D135]] — the evening bonus is off at ~N = 0~ and for a kid with no cutoff.* The Early Bird verdict ignores ~E~; the =EARLY= pill showing at ~E = 0~ is an open backlog item this initiative does not touch.
- *[[file:../decisions.org::#d104][D104]] / [[file:../decisions.org::#d136][D136]] — the reward today:* a white sun or moon (~size-14~) in the banner's left slot, a green ~+R+E~ / ~+R+N~ badge, and a white =EARLY= / =NIGHT OWL= pill in the kid's colour; "no bird at all"; and "no target time, no countdown and no hint of ~N~ before the finish". This design supersedes the first and the countdown clause in part (D148, D149); the "no hint of ~N~" clause stands.
- *[[file:../decisions.org::#d103][D103]] — glyphs outside the emoji set ship as inline SVG.* The bird and bear are inline SVG.
- *[[file:../decisions.org::#d105][D105]] — the stake bar carries no text and no second chip; Nunito (~font-reward~) is for celebratory strings only, never a time.* The countdown stays out of the stake bar and puts its time on the system sans.
- *[[file:../decisions.org::#d115][D115]] — Claude Design flows back only as a handoff recreated in the component tree:* every hex becomes a token, a prototype's JS is a timing spec, never code. The visual spec below came from the handoff "Bonus countdown design exploration", direction 4a, chosen by the human.
- *[[file:../decisions.org::#d119][D119]] / [[file:../decisions.org::#d126][D126]] — no clock mocking.* Tests and dev scenarios stage time by inserting schedule versions relative to the real now.
- *Kiosk fit budget* — five pending chores fit a column at 1280 × 800 with no scroll and almost nothing to spare, so the countdown adds no height.
- *Local time* — all time logic takes a local datetime argument (~BearCub.LocalTime~); no ~DateTime.utc_now()~ in domain code.

* Data Model

No schema change. Everything the countdown needs is already stored: ~early_bird_bonus~ (E) and ~night_owl_bonus~ (N) on ~ScheduleVersion~; per weekday, ~DayEntry.early_bird_cutoff~ (one family-wide ~Time~) and ~DayEntry.night_owl_cutoffs~ (embedded ~{kid_id, cutoff}~, at most one per kid, absent meaning no evening bonus).

** Configuration (SC-1, SC-2)

Runtime config, read in ~config/runtime.exs~ from env vars that new ~services.bear-cub~ module options in ~nix/module.nix~ set ([[file:../decisions.org::#d147][D147]]):

| Key                                          | Env var                               | Default | Meaning                                                 |
|----------------------------------------------+---------------------------------------+---------+---------------------------------------------------------|
| ~:bonus_countdown~, ~lead_minutes:~          | =BEAR_CUB_COUNTDOWN_LEAD_MINUTES=     | 30      | The countdown appears this long before the cutoff       |
| ~:bonus_countdown~, ~seconds_minutes:~       | =BEAR_CUB_COUNTDOWN_SECONDS_MINUTES=  | 5       | At or below this much time left, seconds mode           |

Boot refuses unless both are positive integers and lead > seconds. One value each for the whole app: not per routine, not in the admin UI (PRD Out of Scope). ~KioskLive~ reads the config at mount into assigns and passes milliseconds into ~BearCub.Countdown~.

** Column state

Each kiosk column gains three fields, built in ~KioskLive.build_column~:

- ~countdown_cutoff~ — the cutoff that applies to this kid today as a local ~DateTime~, or ~nil~.
- ~countdown_eligible?~ — the eligibility rule below (Key Behaviors).
- ~countdown~ — the result of ~Countdown.state/5~: ~nil~ or ~%{mode: :minutes | :seconds, remaining_ms: integer, fraction: float}~.

The first two are cached so a tick can recompute the third without reloading.

* Screens / Interfaces

** Kiosk — the banner's left slot (SC-1 to SC-4)

The left slot of each kid's banner shows exactly one of: the *reward* (when ~reveal?~ — the existing rule), the *countdown* (when the column's ~countdown~ is not ~nil~), or *nothing*. The two can never both be due: the countdown requires the routine not complete, the reward requires it complete. Position: absolute, ~left: 16px~, vertically centred in the ~h-20~ (80 px) banner. The centred name and the right-hand group (points pill and gift button) are unchanged. Nothing adds height anywhere in the column, so the five-pending-chore no-scroll budget is untouched ([[file:../decisions.org::#d148][D148]]).

The banner sits above both body views, so a racing kid who opens the reward shop still sees their countdown: the race does not pause for shopping.

*** Countdown — ~KioskComponents.countdown/1~

A function component that renders from assigns only — ~kid~, ~routine~, ~mode~, ~remaining_ms~, ~fraction~; no clock. Minutes and seconds are *separate elements*, ~#countdown-min-{id}~ and ~#countdown-sec-{id}~, each with ~data-mode~, so the grow animation runs once, when seconds mode mounts; between ticks LiveView patches only the text and the dial's inline style.

Minutes mode (lead ≥ remaining > switch):
- Pill: ~h-[60px]~, ~rounded-full~, white at 20 % (as the points pill), padding ~0 18px 0 6px~, flex row, ~gap: 10px~, items centred.
- Dial: 50 × 50 px circle. Ring ~conic-gradient(#fff 0deg Xdeg, rgba(255,255,255,.3) Xdeg 360deg)~ with ~X = fraction × 360~, so it drains clockwise over the lead time. Core: an inset 5 px circle in the routine colour (~--routine-morning~ / ~--routine-evening~).
- Glyph centred in the core, 30 px wide: the bird (stroke ~--routine-morning-content~) in the morning, the bear (fill white) in the evening.
- Number: whole minutes, system sans, 40 px, weight 800, ~tabular-nums~, white, ~line-height: 1~.
- Unit =min=: system sans, 22 px, weight 700, white, ~align-self: flex-end; padding-bottom: 14px~.

Seconds mode (remaining ≤ switch), the escalation:
- Pill: ~h-[70px]~, ~rounded-full~, solid routine colour, ~3px solid~ white border, padding ~0 20px 0 5px~, ~gap: 10px~.
- Dial: 58 × 58 px. Ring ~conic-gradient(C 0deg Xdeg, color-mix(in oklab, C 22%, transparent) Xdeg 360deg)~ with ~C~ the routine content colour (~--routine-morning-content~ / ~--routine-evening-content~) and ~X = fraction × 360~: at the switch the ring refills to a full circle, then shrinks every second. Core: inset 7 px, ~var(--color-base-100)~.
- Glyph: 34 px wide, in the routine ink — morning ~--routine-morning-content~, evening ~--routine-evening~ (never white, which would vanish on the core).
- Number: ~m:ss~, system sans, 56 px, weight 800, ~tabular-nums~, routine content colour. No unit.

Never a bonus amount (~+2~, "earn more") in either mode; the stake chip stays the live ~+R~. No sound. No new hex values: whites and the routine tokens, mixed with ~color-mix~ where the handoff used alpha.

*** Reward — the rebuilt completion icon

Inside the existing ~#completion-icon-{id}~ toggle button, a 96 × 80 px container ([[file:../decisions.org::#d149][D149]]):
- Sun or moon (~hero-sun-solid~ / ~hero-moon-solid~): 56 px, white, ~left: 20px; top: 4px~.
- Badge ~#completion-badge-{id}~: ~left: 62px; top: 4px; z-index: 1~; Nunito 900, 14 px, ~bg-success~ / ~text-success-content~, ~rounded-full~, padding ~4px 7px~, the kid-colour ~border-2~ kept. The number is ~R + E~ or ~R + N~, as today; hidden when forfeited, as today.
- Bonus pill ~#early-bird-{id}~ / ~#night-owl-{id}~ (ids kept as test anchors): ~left: 0; bottom: 6px~; text =EARLY BIRD= or =SLEEPY BEAR=; white ground, kid-colour text, Nunito 900, 14 px, ~rounded-full~, padding ~4px 9px~, ~position: relative; z-index: 1~.
- Peeking glyph: absolute in a wrapper around the pill at ~right: -15px; top: -16px~, *behind* the pill's upper-right corner, so it climbs out of the pill; white; bird 26 px wide, bear 30 px wide. Pill and glyph are one signal: both render or neither, and a fail removes both.
- Replaces the private ~routine_pill/1~.

* Key Behaviors

** ~BearCub.Countdown~ — pure state (SC-1, SC-2, SC-4)

A new pure module: no clock, no config, no database. ~local_now~, the lead time and the seconds switch arrive as arguments.

#+begin_src elixir
@spec state(DateTime.t() | nil, boolean(), DateTime.t(), pos_integer(), pos_integer()) ::
        nil | %{mode: :minutes | :seconds, remaining_ms: pos_integer(), fraction: float()}
def state(cutoff, eligible?, local_now, lead_ms, switch_ms)

@spec next_edge(DateTime.t() | nil, DateTime.t(), pos_integer(), pos_integer()) :: DateTime.t() | nil
def next_edge(cutoff, local_now, lead_ms, switch_ms)
#+end_src

- ~state/5~ is ~nil~ when not eligible, when ~cutoff~ is ~nil~, when ~remaining <= 0~, or when ~remaining > lead~. Otherwise ~:seconds~ when ~remaining <= switch~, else ~:minutes~.
- ~fraction~ drives the dial: ~remaining / lead~ in minutes mode, ~remaining / switch~ in seconds mode.
- Displayed value: in minutes mode ~div(remaining_s, 60)~ where ~remaining_s = div(remaining_ms, 1000)~ — from the lead down to the switch, never =0 min=; in seconds mode ~m:ss~ of ~ceil(remaining_ms / 1000)~ — =5:00= down to =0:01=, then hidden. A tap during =0:01= still earns, matching the strict verdict ([[file:../decisions.org::#d133][D133]]).
- ~next_edge/4~ is the next instant the display changes, or ~nil~ once the cutoff has passed: appearance (~cutoff − lead~), the next whole minute in minutes mode (~cutoff − k·60 s~), the next whole second in seconds mode (~cutoff − k·1 s~), and the cutoff itself. Every edge is measured back from the cutoff, so ticks never drift ([[file:../decisions.org::#d145][D145]]).
- Config validation lives here too (a ~validate_config!/1~ or equivalent called from ~config/runtime.exs~), so the boot rule has unit tests.

** Eligibility (SC-1, SC-3)

Computed in ~KioskLive.build_column~ from data the column already loads, using the version in force *now* ([[file:../decisions.org::#d146][D146]]). A kid is eligible when all hold:

- the routine window is active (~routine_state == :active~) — the night screen never shows a countdown;
- the bonus is on: in the morning ~version.early_bird_bonus > 0~; in the evening ~version.night_owl_bonus > 0~ *and* this kid has a ~NightOwlCutoff~ for today's weekday;
- the routine is not complete and not failed — a failed routine chore forfeits the bonus, so there is nothing left to race for.

The cutoff is the morning's ~Routines.day(version, today).early_bird_cutoff~, or this kid's entry in ~.night_owl_cutoffs~, combined with ~today~ in ~LocalTime.timezone()~. At ~E = 0~ the countdown is hidden even though the =EARLY= pill still shows on a timely finish (the open backlog item); this initiative changes nothing about earning or pricing (PRD Out of Scope).

** Ticking — still one timer (SC-2, SC-4)

The server keeps the clock; the browser only renders ([[file:../decisions.org::#d145][D145]]).

- ~schedule_boundary/2~ arms for the earliest of ~Routines.next_boundary/2~ and every column's ~Countdown.next_edge/4~ — still one timer reference, cancelled before every re-arm ([[file:../decisions.org::#d124][D124]]).
- The message names the edge that won: a window edge or midnight sends ~:boundary~ (the full ~load/3~, as today); a countdown edge sends ~:countdown_tick~.
- ~:countdown_tick~ recomputes only each column's ~countdown~ from the cached ~countdown_cutoff~ and ~countdown_eligible?~ — no database query — then re-arms. A tick every second for the final stretch costs nothing.
- ~:chores_changed~ (a finish or a fail), ~:schedule_changed~ and ~:boundary~ reload as today, which recomputes eligibility and re-arms.
- Today's ~max(ms, 1_000)~ floor guards ~:boundary~ against a hot re-arm; applied to a countdown edge it would skip seconds. A countdown edge takes a small floor instead (about 50 ms).
- Window edges and midnight never collide with a cutoff edge: cutoffs are validated strictly inside their window, so the cutoff always comes first.
- A tick that fires late or early is harmless: the state is recomputed from the actual now, not stepped.
- Sleep and reconnect: a remount computes everything fresh from ~LocalTime.now()~; a tick after the cutoff finds ~nil~. There is no clock skew to handle, because the server's clock decides both the display and the verdict.

** Motion (SC-2, SC-4)

Three keyframes in ~assets/css/app.css~, each with an ~--animate-*~ theme entry ([[file:../decisions.org::#d152][D152]]):

- ~cd-grow~: 420 ms ~cubic-bezier(.34,1.56,.64,1)~, once — ~scale(.7)~ at opacity .4 → ~scale(1.08)~ at opacity 1 at 60 % → ~scale(1)~. On the seconds pill as it mounts.
- ~cd-beat~: 1 s, infinite, ease-in-out — ~scale(1)~ → ~scale(1.14)~ at 12 % → ~scale(1)~ at 30 %. On the seconds-mode dial glyph. It mounts at a second edge, which phases it roughly with the tick; exact phase-locking is not attempted.
- ~cd-fade~: 600 ms to ~opacity: 0~, through ~phx-remove={JS.transition("animate-cd-fade", time: 600)}~ on both pills. It runs whenever a pill leaves: at the cutoff, on a schedule save or a fail, and on finishing, where it cross-fades with the reward appearing.

All three carry ~motion-reduce:animate-none~: under reduced motion the states swap instantly.
