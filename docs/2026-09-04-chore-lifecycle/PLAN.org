# Out-of-scope discoveries land here during implementation instead of being fixed inline. Promoted to v2 candidates at initiative close.

From Story 01:

- The backfill's ~local_date_of/2~ raises a bare ~FunctionClauseError~ naming ~Calendar.ISO.parse_utc_datetime/2~ on an ~inserted_at~ it cannot parse, without naming the offending chore. Unreachable with Ecto-written data (~chores.inserted_at~ is ~TEXT NOT NULL~ and ~strftime~ normalizes every spelling SQLite accepts), and failing loudly is the right direction, but a data-repair scenario would get an unhelpful abort.
- The epoch floor does double duty as the "not yet backfilled" sentinel, and ~chore_fixture/3~'s default ~local_now~ is that same epoch — so a pre-lifecycle row and a row deliberately created with an epoch datetime are indistinguishable to the backfill's guard. Correct today because no production caller passes one.
- A ~%Chore{}~ inserted without ~active_from~ silently takes the epoch floor rather than failing: Ecto omits the nil field and SQLite supplies the default, which is exactly how the ~seeds.exs~ gap went unnoticed. Nothing at the schema level stands behind the field.
- The migration depends on application code and on a named timezone backend — it calls ~BearCub.LocalTime.timezone()~ and ~Application.ensure_all_started(:tzdata)~. Migrations outlive the code around them, so renaming that module, changing the ~:bear_cub, :timezone~ config key, or swapping the ~Tzdata.TimeZoneDatabase~ backend would break a migration that has already run everywhere but must still replay on a rebuilt box.
- Replaying ~down~ then ~up~ inside a single BEAM process raises =duplicate column name: is_recurring=, because the migration file is loaded twice in the same VM and ~up/0~ runs twice. Separate ~mix ecto.rollback~ and ~mix ecto.migrate~ invocations are unaffected, as is a from-scratch create-and-migrate; this bites only someone who later writes a round-trip migration test in one process.
- ~priv/repo/seeds.exs~ still sets ~position~ by hand rather than going through ~Chores.create_chore/3~, which would compute it. Story 01 stamped ~active_from~ there the same way rather than reroute the script; the bypass predates this batch.
- Pre-existing, adjacent: ~mix precommit~ runs ~format~, which rewrites files, rather than ~format --check-formatted~, so the declared verify command cannot fail on formatting.
