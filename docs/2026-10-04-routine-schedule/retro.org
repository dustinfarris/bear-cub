*** The dev server was not running

Stories 03 and 04 each stalled on Tidewave because ~mix phx.server~ had not been started, and Story 05's Deferred carries a dead Tailwind watcher (invalid code signature, re-signed with ~codesign~) as if it were product work. Tidewave's ~project_eval~ reloads code before every eval, so a running server is current for ~lib/~ and ~dev/~; the failure is remembering to run it, plus the gaps the reloader cannot close: ~mix.exs~, ~config/~, and a migration added mid-batch. bear-cub also takes the default port 4000, which every other Phoenix project on the machine takes too.

Ruling: the server is a session precondition the repo provides, not a thing to remember, and it has its own port. The shape is settled: a session-start mechanism probes bear-cub's port, starts ~mix phx.server~ detached when nothing answers, waits for the probe, and says when ~mix.exs~ or ~config/~ is newer than the running server; dev migrates on boot; no per-session tear-down, a by-hand stop instead; the MCP side goes through ~mix tidewave.proxy~ (dep bump), which carries the port per call and registers whether or not the app is up. The exact implementation is open: where the hook lives (bear-cub's ~.claude/settings.json~, a kit hook gated on a CLAUDE.md line, or dotfiles), whether the proxy compiles the project on start, and whether it registers per project or once at user level. Lands as a kit backlog item carrying those questions. Separately and now: Deferred is for product discoveries only, so the Tailwind entry moves to ~docs/learnings.org~ as a dev-environment entry.
